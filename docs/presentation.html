Choix architectural : TaskGroup

Avant — 4 DAGs séparés

  • TriggerDagRunOperator entre chaque étape
  • Latence de polling (15s entre chaque)
  • Code dupliqué (run_soda_check × 3)
  • Logs éparpillés sur 4 DAGs
  • Dépendances fragiles inter-DAGs

Après — 1 DAG + TaskGroups

  • Un seul endroit pour tout le pipeline
  • Pas de latence entre les étapes
  • run_soda_check factorisé dans soda_utils.py
  • UI claire avec groupes collapsables
  • Parallélisation native (transformation + profiling)

Les DAGs standalone sont conservés pour permettre une exécution indépendante de chaque étape si besoin.
